# جُملة (Jumla)

موقع لتعلّم الإنجليزية بكتابة الجمل حرفاً بحرف، لك ولأصحابك. تسمع الجملة، تكتبها، وترى الترجمة العربية ومعنى كل كلمة. فيه قصص، ونصوص استماع مع أسئلة فهم، وقوائم كلمات، وستريك يومي ونقاط ومهام يومية وترتيب بينكم.

- **أنت المدير**: من `/admin` تعدّل أي جملة أو ترجمة أو سؤال، وتضيف دروساً جديدة، وتقرأ بلاغات الأخطاء من أصحابك.
- **التعديل يظهر للجميع فوراً**: المحتوى محفوظ في قاعدة البيانات، فأي حفظ من لوحة المدير يظهر عند أصحابك من أول تحديث للصفحة. وأي تعديل على الكود تدفعه إلى GitHub ينشره Vercel تلقائياً.
- **التقدّم لا يضيع**: شرح كامل في قسم «كيف يُحفظ التقدّم» تحت.

## الإعداد لأول مرة (حوالي 20 دقيقة)

تحتاج ثلاثة حسابات مجانية: **GitHub** و **Supabase** و **Vercel**. أنشئها بنفسك (يمكنك الدخول إلى Vercel و Supabase بحساب GitHub).

### 1) Supabase: قاعدة البيانات وتسجيل الدخول

1. من [supabase.com](https://supabase.com) أنشئ مشروعاً جديداً (New project). احفظ **كلمة مرور قاعدة البيانات** في مكان آمن.
2. انسخ الملف `.env.example` باسم `.env.local` في مجلد المشروع، واملأه:
   - `NEXT_PUBLIC_SUPABASE_URL` والمفتاح العام: من زر **Connect** → **App Frameworks** → **Next.js**، والصق السطرين كما هما. اسم سطر المفتاح قد يكون `NEXT_PUBLIC_SUPABASE_ANON_KEY` أو `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`، والاثنان يعملان. لا تستخدم المفتاح السري (secret / service_role).
   - `SUPABASE_DB_URL`: من زر **Connect** أعلى الصفحة → **Session pooler** → انسخ الـ URI وضع كلمة مرور قاعدة البيانات مكان `[YOUR-PASSWORD]` (احذف القوسين، واكتب كلمة المرور كما هي حتى لو فيها رموز).
   - `ADMIN_EMAIL`: إيميلك أنت.
   - `INVITE_CODE`: كود تعطيه لأصحابك ليسجّلوا (مثلاً `tea-moon-482`).
3. تأكيد الإيميل عند التسجيل يحتاج خدمة إرسال إيميل خاصة بك (SMTP). خطواتها في قسم «6) تأكيد الإيميل عند التسجيل» تحت، وتقدر تسويها بعد ما يشتغل الموقع.

### 2) تشغيل الموقع على جهازك

```bash
npm install
```

```bash
npm run db:seed
```

الأمر الثاني ينشئ الجداول وقواعد الحماية، ويحفظ إيميلك وكود الدعوة، ويضيف المحتوى الأولي (6 قصص، 8 نصوص، 3 قوائم كلمات). تقدر تشغّله أكثر من مرة بأمان، فهو لا يحذف شيئاً ولا يغيّر تعديلاتك.

> **بديل بدون أوامر:** افتح `supabase/setup.sql`، وغيّر الإيميل والكود في القسم المعلَّم بـ ✏️، ثم الصقه كله في **SQL Editor** في Supabase واضغط **Run**.

```bash
npm run dev
```

افتح `http://localhost:3000`، ثم سجّل حساباً بإيميلك (نفس `ADMIN_EMAIL`) وكود الدعوة. حسابك يصبح مديراً تلقائياً.

### 3) GitHub: حفظ الكود

أنشئ مستودعاً **خاصاً (Private)** على GitHub، ثم ارفع المشروع إليه (بـ GitHub Desktop أو بالأوامر):

```bash
git init
```

```bash
git add -A
```

```bash
git commit -m "Jumla"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/USERNAME/jumla.git
```

```bash
git push -u origin main
```

الملف `.env.local` لا يُرفع (موجود في `.gitignore`)، فمفاتيحك لا تصل إلى GitHub.

### 4) Vercel: نشر الموقع على الإنترنت

1. من [vercel.com](https://vercel.com) اضغط **Add New → Project** واختر المستودع.
2. في **Environment Variables** أضف أول سطرين من `.env.local` (رابط المشروع والمفتاح العام) بنفس أسمائهما وقيمهما، ثم اضغط **Deploy**. لا تضف `SUPABASE_DB_URL` هنا، فالموقع لا يحتاجه.
3. انسخ رابط موقعك (مثل `https://jumla-xyz.vercel.app`)، وارجع إلى Supabase → **Authentication → URL Configuration**:
   - **Site URL**: رابط موقعك.
   - **Redirect URLs**: أضف `https://jumla-xyz.vercel.app/auth/callback` و `http://localhost:3000/auth/callback`.

من الآن، كل `git push` ينشر نسخة جديدة تلقائياً خلال دقيقة أو اثنتين، ويحصل عليها كل أصحابك.

### 5) النسخ الاحتياطي اليومي

في GitHub: **Settings → Secrets and variables → Actions → New repository secret** وأضف:

- `SUPABASE_DB_URL` (نفس قيمة `.env.local`): **مطلوب**.
- `BACKUP_PASSPHRASE`: **مطلوب**. كلمة سر طويلة (16 حرفاً على الأقل) تُشفَّر بها كل نسخة (AES-256)، فما يقدر أحد يفتح النسخة حتى لو حمّلها. بدون هذه الكلمة ما تُحفظ أي نسخة.
- `NEXT_PUBLIC_SUPABASE_URL` والمفتاح العام (باسم `NEXT_PUBLIC_SUPABASE_ANON_KEY` أو `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`): اختياريان، ويُبقيان مشروع Supabase المجاني نشطاً.

**كلمة سر النسخ:** هذا الأمر في PowerShell يولّد كلمة قوية وينسخها مباشرة، فما تظهر على الشاشة:

```powershell
$b = New-Object byte[] 24; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b) | Set-Clipboard
```

الصقها في قيمة الـ secret، **واحفظها في مكان آمن** (مثل مدير كلمات المرور). بدونها ما تقدر تفتح أي نسخة، ولا أحد يقدر يسترجعها لك. وإذا غيّرتها لاحقاً، النسخ القديمة تبقى تُفتح بالكلمة القديمة فقط.

ثم من تبويب **Actions → Daily database backup → Run workflow** شغّله مرة لتتأكد أنه يعمل. بعدها يعمل وحده كل يوم، وتجد النسخ في صفحة كل تشغيل تحت **Artifacts** باسم `jumla-backup-encrypted-…` (تُحفظ 90 يوماً).

**قبل ما تخلّي المستودع عاماً (public):** النسخ اللي انحفظت قبل إضافة التشفير (باسم `jumla-backup-رقم`) غير مشفّرة، وفيها إيميلات أصحابك. احذفها مرة واحدة: **Actions → Delete old unencrypted backups → Run workflow** ← اكتب `DELETE` في الخانة ← **Run workflow**. ما يحذف شيئاً إذا ما فيه نسخة مشفّرة واحدة على الأقل، والنسخ المشفّرة تبقى.

### 6) تأكيد الإيميل عند التسجيل

خدمة الإيميل المدمجة في Supabase ترسل فقط لإيميلات أعضاء فريق مشروعك، وعدد قليل جداً في الساعة، فرسائل التأكيد ما بتوصل لأصحابك. الحل: ترسل الرسائل من Gmail حقك (مجاناً، حوالي 500 رسالة في اليوم).

1. **كلمة مرور تطبيق من Google:** افتح `myaccount.google.com` ← **Security** ← فعّل **2-Step Verification** إذا مو مفعّل ← ارجع وابحث عن **App passwords** ← اكتب اسماً مثل `Supabase` ← **Create** ← انسخ الكلمة (16 حرفاً).
2. **Supabase ← Authentication ← Emails ← SMTP Settings** ← فعّل **Enable Custom SMTP** واملأ:
   - **Sender email**: إيميلك في Gmail
   - **Sender name**: `جُملة`
   - **Host**: `smtp.gmail.com`
   - **Port**: `587`
   - **Username**: إيميلك في Gmail
   - **Password**: كلمة مرور التطبيق من الخطوة 1 (مو كلمة مرور Gmail العادية)
   ثم **Save**.
3. **Supabase ← Authentication ← Emails ← Templates:**
   - **Confirm signup**: الصق محتوى `supabase/email-templates/confirm-signup.html`، والعنوان مكتوب في أعلى الملف.
   - **Reset password**: نفس الشيء مع `supabase/email-templates/reset-password.html`.
4. **Supabase ← Authentication ← Sign In / Providers ← Email** ← شغّل **Confirm email** ← **Save**.
5. جرّب: سجّل حساباً بإيميل ثاني عندك، ولازم توصلك رسالة «أكّد إيميلك في جُملة».

## دعوة أصحابك

أرسل لهم رابط الموقع وكود الدعوة. يفتحون **عندي كود دعوة** ويسجّلون. تقدر تغيّر الكود من **لوحة المدير → الإعدادات** في أي وقت، ومن سجّل قبل ذلك لا يتأثر.

## لوحة المدير `/admin`

- **القصص / النصوص / قوائم الكلمات**: أضف أو عدّل أو رتّب. في محرر الجمل تُقسَّم الكلمات تلقائياً لتكتب معنى كل كلمة. وفيه أيضاً «إضافة عدة جمل دفعة واحدة» بصيغة `English | العربية`.
- **مسودة**: أزل علامة «منشور» لتجهّز درساً لا يراه غيرك، ثم انشره متى أردت.
- **الأرشفة بدل الحذف**: أي شيء تؤرشفه يختفي عن المتعلمين، لكنه يبقى ويبقى التقدّم المرتبط به، وتقدر تسترجعه من «عرض المؤرشف».
- **البلاغات**: كل جملة فيها زر «أبلغ عن خطأ». البلاغ يصلك هنا، وزر «عدّل» يفتح الجملة نفسها مباشرة.
- **المستخدمون**: تقدّم كل واحد (للعرض فقط)، وتقدر تعطي صلاحية المدير لغيرك، أو تحذف حساب عضو. الحذف يمنعه من الدخول، لكن سجل تقدّمه يبقى في قاعدة البيانات.
- **الإعدادات**: كود الدعوة، وإيميلات المدراء، وتحميل نسخة JSON فورية من كل شيء.

## كيف يُحفظ التقدّم (ولماذا لا يضيع)

1. **على الخادم، مربوطاً بالحساب**: يدخل صاحبك من أي جهاز فيجد تقدّمه.
2. **على الجهاز أولاً**: كل جملة تُكتب تُحفظ فوراً في المتصفح (IndexedDB)، ثم تُرسل للخادم. لا تُحذف من الجهاز إلا بعد أن يؤكد الخادم استلامها. انقطع الإنترنت؟ أُغلق التبويب؟ انتهت الجلسة؟ تبقى محفوظة وتُرسل تلقائياً عند العودة. المؤشر أعلى الصفحة يوضح الحالة («محفوظ» أو «بانتظار الاتصال»).
3. **بدون تكرار**: لكل خطوة معرّف فريد، فإعادة إرسالها لا تُحسب مرتين.
4. **التقدّم يزيد ولا ينقص**: سجل الخطوات لا يقبل إلا الإضافة، والإحصائيات تُحسب منه في قاعدة البيانات، والنقاط يحسبها الخادم لا الجهاز.
5. **لا يوجد حذف**: قواعد الحماية لا تسمح لأحد (ولا حتى للمدير) بحذف أو تعديل التقدّم، وحذف المحتوى أرشفة فقط.
6. **نسخة احتياطية يومية مشفّرة** على GitHub لمدة 90 يوماً، ونسخة JSON فورية من لوحة المدير.

## استرجاع نسخة احتياطية (للطوارئ فقط)

حمّل الـ Artifact من GitHub وفكّ ضغطه، فتجد ملفاً مثل `jumla-backup-YYYY-MM-DD.tar.gpg`. افتح PowerShell في نفس المجلد وفكّ التشفير. برنامج `gpg` يجي مع Git، ويطلب كلمة سر النسخ في نافذة صغيرة:

```powershell
& "C:\Program Files\Git\usr\bin\gpg.exe" --output backup.tar --decrypt jumla-backup-YYYY-MM-DD.tar.gpg
```

```powershell
tar -xf backup.tar
```

يطلع لك ملفان: `public-YYYY-MM-DD.dump` و `auth-YYYY-MM-DD.dump`. بعدها (مع تثبيت أدوات PostgreSQL 17):

```bash
pg_restore --clean --if-exists --no-owner -d "$SUPABASE_DB_URL" public-YYYY-MM-DD.dump
```

إذا كانت كلمة مرور قاعدة البيانات فيها رموز مثل `@ # / ?`، فالأسهل أن تغيّرها في Supabase إلى حروف وأرقام قبل الاسترجاع، لأن أمر `pg_restore` لا يقبل هذه الرموز في الرابط كما هي.

إذا كان المشروع جديداً بالكامل، شغّل `npm run db:migrate` أولاً، ثم استرجع ملف `auth-…dump` بنفس الأمر بدون `--clean` قبل ملف `public`.

## ملاحظات عن الخطة المجانية

- Supabase يوقف المشروع المجاني مؤقتاً بعد أسبوع بلا أي نشاط. البيانات لا تُحذف، وتعيد تشغيله بزر من لوحة Supabase. النسخ الاحتياطي اليومي (مع السرّين الاختياريين) يمنع هذا.
- النطق يستخدم الصوت المدمج في المتصفح، فيختلف قليلاً بين الأجهزة. يعمل في Chrome و Edge و Safari.

## للتطوير

| الأمر | ماذا يفعل |
| --- | --- |
| `npm run dev` | تشغيل الموقع على جهازك |
| `npm test` | الاختبارات (منطق الكتابة، والستريك، وطابور الحفظ، وقاعدة البيانات داخل PGlite) |
| `npm run lint` / `npm run typecheck` / `npm run build` | الفحص والبناء |
| `npm run db:migrate` | تطبيق ملفات `supabase/migrations` الجديدة |
| `npm run db:seed` | نفس السابق، مع إضافة المحتوى الأولي |
| `npm run sql:build` | إعادة توليد `supabase/seed.sql` و `supabase/setup.sql` من `content/*.json` |
| `npm run hints:check` | يعرض الكلمات التي ليس لها معنى عربي في المحتوى الأولي |

**تعديل قاعدة البيانات لاحقاً:** أضف ملفاً جديداً مثل `supabase/migrations/0005_something.sql` (لا تعدّل الملفات القديمة)، ثم شغّل `npm run db:migrate`.
